**代码根因（已核对 src/main.py:667-711）**

```python
if d_ball < RESTART_AVOID_RADIUS_M + 0.35:          # 1.8 m
    target = _away_from_ball_point(..., 2.0)
    if elapsed <= STOP_VACATE_WINDOW_S:              # 0.6 s
        p.omni_move_toward(target, speed=STOP_VACATE_SPEED)   # 1.5 m/s
    continue                                        # ← 窗口后什么也不做
p.action = "stopped"; p.stop()
```

- `omni_move_toward(target, 1.5)` 是**持续速度指令**，0.6 s 窗口到期后 `continue` 既不下发新指令也不 `p.stop()`，机器人会继续朝 2.0 m 外的目标点滑行约 1.3 s；裁判从**宽限期结束（+1.5 s）起**再累计 0.3 m 路径 → 必然越线（本场三次 0.303/0.301/0.330 m，都是「刚好超一点」）。
- v2.4 把 STOP_VACATE_WINDOW_S 1.2→0.6、速度 2.0→1.5、**删掉 STOP_CRAWL_SPEED 爬行**，本意是缩短移动窗口，但删爬行 + 保留 `continue` 的组合让宽限后的净残速更大，**比 v2.2/v2.3 更危险**（v2.3 两次 0.307/0.313 m，同样边际超标）。
- 另一层诱因：三次都是**我方机器人本来就在球旁 0.2–0.7 m**（我方把球碰出边线后去抢点）。摆球开始时已在 1.45 m 风险圈内，撤离是刚需；此时靠「快撤」无法既撤出 1.45 m 又不超 0.3 m 路径（从 0.2 m 撤到 1.8 m 至少 1.6 m 位移）。

## 6 可执行战术建议（按预期收益排序，只改 src/main.py / src/player.py / src/param.py）

### 建议 1（最高优先）：修 `_act_stopped` 的「窗口后滑行」+ 恢复慢爬，消灭 M-02

- **改动位置**：`src/main.py:698-710`（`_act_stopped` 的 vacate 分支）；`src/param.py`。
- **具体改法**：
  1. 把 `if elapsed <= STOP_VACATE_WINDOW_S: ... continue` 改成 `if elapsed <= STOP_VACATE_WINDOW_S: p.omni_move_toward(target, speed=STOP_VACATE_SPEED); continue`，**窗口后改为 `p.omni_move_toward(target, speed=STOP_CRAWL_SPEED)`（不再 `continue`）**，即恢复 v2.2 的宽限后爬行，且永远不发「无指令」的滑行；
  2. `STOP_VACATE_SPEED 1.5 → 1.2`，`STOP_CRAWL_SPEED 0.0 → 0.08`（0.08 m/s × 2 s = 0.16 m，留 0.14 m 余量）；
  3. 兜底：非 vacate 分支保持 `p.stop()`（已有），并确保任何走到 `p.stop()` 的分支都先结束 omni 任务。
- **预期收益**：本场 3 张 M-02（罚下 90 s、其中 230.8 s 失球正处在 robot3 罚下的 2v3 窗口）→ 0；同类历史 5 次（v2.3 2 次、v2.5 3 次）一起消除，等于每场少 1–2 次 2v3。
- **风险**：宽限后爬行 2 s ≈0.16 m，仍可能因裁判窗口更长而边际超标；且若爬行结束时还<1.45 m，对方主罚触球瞬间有 R-07（illegalPosition）风险。**对冲**：把爬行速度压到 0.05–0.08，并在 `_act_normal` 加一条「球距边线 <0.5 m 且我方最近机器人 <1.2 m 时，先退到 1.6 m 再抢」，从源头避免摆球期身处风险圈内。

### 建议 2：`_set_play_kick_plan` 只传给「在场且靠前」的队友，力度随距离缩放

- **改动位置**：`src/main.py:292-344`（`_set_play_kick_plan`），调用处 `src/main.py:566`。
- **具体改法**：
  1. 给函数加 `active_ids`/`players` 参数（`_act_our_set_play` 已有 `players`），遍历队友时**跳过 `is_penalized` / `is_fallen` / 不在 `players` 里的机器人**——本场 mate 选中等待区 robot3 就是这个 bug；
  2. 目标点加方向约束：`if target[0] < ball.x - 0.6: target = (ball.x + 1.2, clamp(ball.y*0.4,-2.4,2.4))`（**第一脚永不朝己方球门/球门后**，违反「定位球乌龙」条款的路径直接剪掉）；
  3. 力度按距离：`power = clamp(2.0 + 0.45 * dist(ball, target), 2.0, 4.0)`（本场 1.9 m 传球用了 3.6 力度，球滚 8.2 m；改成 ≈2.9 后滚距 <4 m）。
- **预期收益**：直接消灭本场失球 1（自摆乌龙）；同时减少「短传越过接应点送对方门球」的隐性丢球。
- **风险**：可选接应点变少、短传更保守 → 部分定位球退化为向前推；若 `mate` 过滤后无人可传，走原有 fallback 向前推，风险可接受。

### 建议 3（次优先）：定位球 taker 选「球后方」的人，而不是「离球最近」的人

- **改动位置**：`src/main.py:530-596`（`_act_our_set_play`）的 taker 选择与 approach 逻辑。
- **具体改法**：先算 `kick_dir`，再 `taker = min(players, key=lambda p: dist(p.pose.x, p.pose.y, ball.x - 0.45*cos(kick_dir), ball.y - 0.45*sin(kick_dir)))`；并把 `_set_play_kick_plan` 的目标在「球贴边线（|ball.y| > half_w−0.4 或 |ball.x| > half_l−0.4）」时改成**沿边线向中场斜插**（要求 `|sin(kick_dir)| <= 0.55`，即 dx 至少是 dy 的 1.8 倍），避免 taker 为站到球后而绕出场地。
- **预期收益**：本场我方 19 次界外球多次 12–32 s 才首触（690.7 s 的角旗球浪费 9.3 s，taker 绕到 (7.56,−4.78) 场外再回来）；改后多数应 <2 s 出脚，少 2–3 次 dead ball + 2 次「第一脚出界」retake。
- **风险**：taker 可能是更远的那台，出球更慢；沿边线的传球容易被对方边线夹抢 → 被抢断概率上升。建议只在这一条上做小步试跑，观察 `set_play_retake` 与「我方定位球后 5 s 内球权丢失率」两个指标。

## 7 一句话结论

**本场最大失分点不是防守，而是「自伤」：3 张 M-02（90 s 罚下、其中 1 球在 2v3 期间丢）+ 1 次定位球传球选中被罚下队友直接自摆乌龙，丢掉 2 球；最大亮点是 v2.5 的挤球与门将粘滞明显改善（min_pair<1m 4.7% 历史最好、门将切换 7 次），却以 54.2% 球在己方半场换来了中场失控。**
