## 6 v2.17 建议（≤3 条最小改动，全部落在 src/player.py guard() 与 src/main.py presser 分支）

### P0-1 门将「预测过线点」站位（治 5/5 失球的 dy 0.6–0.9 m）
- **代码**：`src/player.py` `guard()`（v2.15 约 :838-870，`if ball.x < 0.0:` 分支）。
- **改动**：球在己方半场且有速度（用 `store.ball_prev` 差分得 (vx,vy)，已有 `_ball_speed_mps` 可扩展为 `_ball_velocity_mps`）时，把 `cover_y` 从 `clamp(ball.y*1.0,±1.15)` 改为**过线点预测**：
  `y_pred = ball.y + (goal_line_x - ball.x) * (vy/vx)`，`cover_y = clamp(y_pred, ±(goal_width/2 - 0.15))`；当 `vx > -0.3`（球未朝门走）或预测点超出禁区时回退现有逻辑。
- **参数**：`KEEPER_PREDICT_MIN_SPEED_MPS = 0.4`、`KEEPER_PREDICT_X_MARGIN_M = 1.0`（只对球距门线 ≤1.0+? 更远的球用当前逻辑）。
- **预期**：本场 5 球过线点相对门将 y 的误差 0.6–0.9 m；用轨迹预测误差可降到 0.2–0.3 m（球速 1.4–2.7 m/s 时直线度很高），至少 3/5 可封堵/减速。
- **风险**：被折射球预测错误；用「clamp 到球门宽度 ±1.15」兜底，最多回到现状。

### P0-2 门将 clear 门限 + 卡住自恢复（治 G4 的 6.0 s 卡死、G1/G2/G3/G5 的「追球离线」）
- **代码**：`src/player.py` `guard()` 的 `if d_ball < KEEPER_CLEAR_RADIUS_M:` 分支。
- **改动**：①`KEEPER_CLEAR_RADIUS_M 1.35 → 0.85`，并加 `ball_speed < KEEPER_CLEAR_MAX_BALL_SPEED_MPS(0.6)` 才允许 `kick()`（快球不追，回门线站位）；②记录 `store.keeper_clear_since`：`kick()` 后若 0.8 s 内球位移 <0.2 m → `release_kick()` 并 `walk_to(home)`（回门线），本场 6/10 段 `guard:clear` 属于这种「球没动」；③球在门将身后（`ball.x < pose.x - 0.05`）时永不 kick。
- **预期**：G4 的 6.0 s 卡死 → 0；其余 4 球门将留在 x=−6.8 门线，配合 P0-1 的 y 预测可覆盖门宽。
- **风险**：0.85–1.35 m 的慢球不再解围（由非门将 presser 处理）；但现状是「解围失败 + 离线」，净收益为正。

### P1 抢球「去手递 + 提速」（治 G1/G2/G3 的换人与 0.4 m/s 接近）
- **代码**：`src/main.py` `_act_normal` 的 `if forced_presser is not None:` 死球分支（v2.15 约 :580-620）。
- **改动**：①`PRESSER_DEADBALL_APPROACH_M 0.45 → 0.30`；②approach 用 `omni_move_toward(ball + 0.30*unit(ball→own_goal), speed=PRESSER_DEADBALL_SPEED=1.6)` 替代 `walk_to(..., avoid_robots=True)`（球 1.2 m 内时 `avoid_robots=False`，允许贴身抢）；③`store.presser_until = context.now + 1.0` 让 forced_presser 在球静止期间**粘住 1 s**，禁止 G1/G3 那种「robot1→robot3」手递；④`d_ball < 0.55` 时直接 `kick(朝对方半场边线, KICK_POWER_CLEAR)`。

### 附带发现（不改代码，写进记录）
- **v2.16 的 `POST_CONCEDE_HOLD_S=3.0` 实际是死代码**：每次失球后进入 READY 13.4–31.7 s + SET 5 s，playing 最早在失球后 ~18 s 开始，3 s 窗口早已过期。若 Lead 想保留该规则，应改为「下次 playing 开始后 5 s 内生效」；否则它不会影响任何一球。

## 7 一句话结论

**这不是纪律问题也不是代码正确性问题：我们在 4:2 领先后，被对方同一招（robot4 停球 1.6–1.9 s + 地滚球）连打 3 次，因为「抢球的人手递手换、门将 clear 追球离线、门将 y 跟球不跟过线点」——先修门将（预测过线点 + clear 门限/自恢复），再修 presser（去手递 + 提速），比任何新战术都值。**
