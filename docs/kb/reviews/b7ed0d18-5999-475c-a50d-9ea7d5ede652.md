## 5) 罚单归因：`inactiveRobot robot1@339.212`（M-05）

- **规则**：`inactiveRobot`——球 3 m 内我方机器人「几乎不动」超过 10 s。
- **测量**：`inactiveDuration = 12.000 s`（阈值 10000）；`ballDistance = 0.364 m`（阈值 3.0）；positions `robot=[6.1517,1.1139,0.5457]`、`reference=[6.1516,1.1137,0.5457]`（20 s 位移 <1 mm）、`ball=[6.5156,1.1130,0.1100]`；`outcome=incapableRobot 30 s`；zone `away_goal_area`。
- **当时 phase/action**：`get_phase = NORMAL`（PLAYING、未暂停、无 set play），动作序列连续 20.1 s 为 `attack:goal_line_approach`（`instrfull` 逐帧确认），无任何 `kick`。
- **代码根因（`src/player.py:855-875`）**：
  1. 当 `ball.x > half_l - 1.0`（6.0）且 `|ball.y| ≤ goal_half + 0.6`（1.9）进入「门线补射」分支；
  2. 若 `pose.x <= ball.x - 0.2` → `attack:goal_line_approach`，`walk_to((ball.x - 0.45, clamp(ball.y)))`；
  3. 否则 → `attack:goal_line_shot` + `kick`。
  本场：ball.x=6.516 → 接近目标 = **6.066**，射门门限 = **6.316**。而 `walk_to` 的到位容差 `ARRIVE_DIST = 0.15`（`src/param.py:49`）→ 机器人最多只能走到 `6.066+0.15 = 6.216`。**6.216 < 6.316：射门门限位于到位容差之外 0.10 m，永远不可达** → 每帧都判 approach、`walk_to` 已到位、于是站死，直到被 M-05 罚下。这不是 v3.3b 引入的：该分支自 v2.16 起一字未改（v3.3b 的三处几何修复在 `main.py` 摆球/`player.py` line_clear，未触及此段；v3.3b 的 line_clear 加「只处理场内球」反而让门前球更少被顺手处理）。
- **历史修复被回退**：v2.21 `7cc8116` 曾修此死锁（#23：距球 ≤0.55 m 直接射），但 v3.0（`f0af8b5`）整体 restore v2.16 时把修复丢了，v3.3b 继承。
- **同族两场证据**：本场（ballDistance 0.364、robot (6.15,1.11)、ball (6.52,1.11)）+ v2.17 #15 `230b0f05`（inactiveRobot robot3@485.226，robot (6.142,−0.411)、ball (6.605,−0.333)、ballDistance 0.469、duration 40.0）——几何与动作同源。
- **代价**：20.1 s 站死 + 30 s 罚下（少一人 30 s）+ 本场第二次同型死锁又造成 30 s `global_game_stuck`；总计 ≥80 s 无效时间。本场因对手弃赛没有付出比分代价，真实对局中这是「把球权和时间白送对方」。

## 6) 可执行战术建议（≤3 条，落到代码/参数）

1. **P0 — 补回 v2.21 #23 的「贴近即射」：门线补射分支先判距离再判方位。** 在 `src/player.py` 门线分支（`ball.x > half_l-1.0` 且 `|ball.y| ≤ goal_half+0.6`）最前面加：
   ```python
   d_line = dist(self.pose.x, self.pose.y, ball.x, ball.y)
   if d_line <= GOAL_LINE_SHOT_DIST_M:      # 新参数 0.55
       self.action = "attack:goal_line_shot"
       self.kick(angle_to(ball.x, ball.y, half_l+0.5,
                clamp(ball.y*0.5, -(goal_half-0.2), goal_half-0.2)),
                SHOOT_POWER_MAX)
       return
   ```
   预期收益：根除本场 2 次死锁（20.1 s + 24 s）与 inactiveRobot（30 s），并让「球停在对方门线前 1 m 内」变成得分机会而非停摆。风险：从侧后方 0.55 m 起脚可能打偏出底线（aim_y 已有 ±(goal_half−0.2) 夹取）；验收口径 = 2 场内 `inactiveRobot=0`、`global_game_stuck=0`、门线区（ball.x>6.0、|y|<1.9）静止球在 2 s 内完成起脚 ≥90%、M-02/R-06/R-07 保持 0。证据 = 本场 + 230b0f05 两场。
2. **P1 — 加「进攻死锁看门狗」兜底。** 任何 `attack:*` 动作连续 `STUCK_KICK_TIMEOUT_S=3.0` 无位移（<0.15 m）且距球 ≤1.0 m → 强制 `kick` 一次（朝球门/边线方向），并 `release_kick()` 重置；只对本方进攻段（NORMAL、球在对方半场）生效。预期：本场三次死锁（31.9 s / 19.9 s / 29.4 s）都能压到 3 s 内，避免 inactiveRobot 与 `global_game_stuck`；风险：乱踢可能把球踢出底线送对方门球（代价小于 30 s 罚下 + 30 s 停摆）；验收 = 连续 2 场「死锁 → 触球 ≤3 s」且 oobCaused 上升 ≤2。
3. **P2 — 本场列入「无效参考场」，v3.3b 验收样本重算并补 inactiveRobot 口径。** 对手未参赛（0 触球、away_ready=None ×7、ready 271.9 s）→ 不能作为 v3.3b 两场验收之一；`records.md` 的「验收全项达标」应改为「只验证纪律项（M-02/R-06/R-07=0），战术项无效」；同时把 `inactiveRobot` 加进验收清单（此前 v3.3b 验收只看 M-02/R-06/R-07，漏了这项，导致本场罚单被忽略）。下一场需真实对手复测 v3.3b 几何修复（本场 0 次对方摆球/界外球，三处修复一次都没被触发）。
