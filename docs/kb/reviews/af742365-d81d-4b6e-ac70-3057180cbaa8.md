### G1 详述（门将横移机制，本场核心）

`/tmp/ra/instr22.py`（载当前 src=v2.23b 回放本场，逐帧重算 `guard()` / `walk_to()` 命令）在 G1 窗口的日志：

1. **74.61–74.92**：`guard:home` 目标 `(−6.8, −1.15)`，keeper 已到达（`arr=True`），合理。
2. **75.04**：球速升到 3.45 m/s、vx≈−2.4 → 过线点预测触发，`cover_y` 从 −1.15 **翻到 +1.15**（目标点跳变 2.3 m）。
3. 此时 keeper pose `(−6.72, −1.10, θ=−0.75)`，到新目标距离 2.25 m > `OMNI_DIST=1.0` → 走 `walk_to` **远距分支**；目标航向 ≈1.61 rad、`angle_err=2.36 > TURN_THRESHOLD(0.5)` → 每帧只下发 `set_velocity(0, 0, +2.0)` = **原地转身**。
4. **75.04–77.34（2.3 s）**：命令一直是 (0,0,±2.0)，**零平移电压**；θ 实际只从 −0.75 变到 +0.17（等效约 0.4 rad/s，远低于指令 2.0），直到 77.45 球出界转 STOPPED，keeper 仍停在 (−6.68,−1.09)。
5. 球 77.67 从 y0.63 过线，keeper dy=+1.76 —— **2.3 s 内一次横移都没有发生**。

**机制结论**：门将横移执行走的是 `walk_to` 远距分支（先转身再前进）；当预测 `cover_y` 因“当前球位 → 过线点预测”切换而跳变时，守门员把全部时间花在转身，来不及横移。这不是“预测算错”，而是“预测对了但执行层不会横移”。G3 同机制：keeper 初始 cover_y=+1.15（球 y3.37），球横穿到 −1.08 需要 2.3 m 横移，keeper 却原地转了约 150°（yaw 0.71→−1.88，2.3 s）、仅移动 0.10 m。G4/G5 因球过来太快（0.8–1.2 s）更没机会。

**A/B 量化**：被进球前 2 s 内“门将实际横移 / 所需横移”比例（全版本同口径）——v2.11 0.50、v2.17a 0.01、v2.17b 0.38、v2.20 0.08、v2.21 0.31、v2.22 0.39、v2.23b **0.04**（本场逐球 0.04 / 4.99 方向反 / 0.04 / 0.26 / 0.03）。v2.22 的 `guard:omni_home`（横向 omni 平移）在同样场景至少能平移，v2.23b 回滚后彻底失效。

## 5 ≤3 条可执行建议

1. **P0｜门将横移改 omni 平移 + cover_y 迟滞**（`src/player.py::guard` 末尾）
   - 改法：保留 `cover_y`/预测不变，在 `walk_to(home, ...)` 前加：
     `if abs(home[1] - self.pose.y) > KEEPER_TRACK_OMNI_DY_M (0.35) and dist(ball, pose) > KEEPER_CLEAR_RADIUS_M + 0.2:` → `action="guard:omni_home"` + `omni_move_toward((home[0], home[1]), KEEPER_TRACK_OMNI_SPEED_MPS=1.6)`（复用 v2.22 已实测有效的路径）；同时用 `store.keeper_cover_y` 做迟滞：`|new - stored| > KEEPER_COVER_HYST_M (0.3)` 才更新，避免预测在“当前球位/过线点”之间抖动。
   - 预期收益：被进球前 2 s 门将 coverage 从 0.04 提升到 ≥0.4（v2.22 实测 0.39）；G1/G3 型横穿慢球可被扑到。
   - 风险：omni 平移会经过小禁区边线/球门柱附近，需要 x 限制在 `−(half_l−KEEPER_LINE_INSET_M−0.05)`；被对手近距离抽射时 omni 可能与 clear 冲突 → 保留 `dist(ball) <= CLEAR_RADIUS+0.2` 时走原 walk_to/clear。

2. **P0｜goalKick 第一脚方向与外脚侧几何**（`src/main.py::_set_play_kick_plan` 的 `GOAL_KICK` 分支）
   - 改法：goalKick 目标改为**传给侧翼**（`|target_y - ball.y| ≥ 1.2 m` 且 `|dir_y| ≥ 0.5`），不要“朝 +x 直塞正中”；taker 接近点改为 `ball − kick_dir*SET_PLAY_TAKER_APPROACH_M` 且要求该点在**小禁区内侧**（`x ≥ −7 + 0.6`），即从门线侧绕后，避免从场内侧把球顶向自家门线（本场 221.6–222.28 事故）。
   - 预期收益：goalKick 自出界 0（本场 1/1 自毁），首触中位从 8 s 降到 ≤5 s；对方 5 次犯规给的 5 次 retake 至少有 1 次能形成推进。
   - 风险：side pass 可能被对方边路抢断；若小禁区内无接应队友则回退为“向两侧边线大脚”（仍不朝中路/自家门）。

3. **P1｜己方三区静止球强制 presser + 倒地期清球**（`src/main.py::_act_normal` 或 `player.py::attack` 分支）
   - 改法：球速 <0.25 m/s 持续 ≥1 s 且 `ball.x < −1.5` 时，**跳过“门将/等待”角色分配**，最近的非门将直立球员直接 `attack:clear`（朝边路安全方向，power 按距离）；若全队只剩 1 台直立，该球员也必须去清球而不是站位。对应本场 33 段 static、2 s 内触球仅 3 次；以及 501–509 三台倒地期间球静止 2 s 无人处理。
   - 预期收益：static 段 2 s 内触球率从 11%（3/27）提到 ≥30%；减少“球停在自家半场慢慢等人来”的二次失球。
   - 风险：更激进的上抢会增加 R-06/犯规（仅在 open play 生效，不在对方摆球期）；倒地/爬起期间指令可能不被执行 → 需配合 framework 侧 get_up 超时（另一条线）。
