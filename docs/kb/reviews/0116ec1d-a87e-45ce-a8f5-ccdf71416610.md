## 2 本方风险事件与关键帧

### 2.1 M-02 `stopped_motion` @ sim 118.99 robot2（0.3348 m / 2372 ms）

**T1 的假设**：「0.12×2.37 ≈ 0.285 m + 残余速度超 0.3」。**帧级数据不支持这个算法**，实际是：

| 时刻 | 事实 |
|---|---|
| ~115.4 s | 我方 112.57 角球被踢出后球越过对方底线（球心 3 帧内到 `7.14,-4.52`，越 7.135 判定线）→ GameControl 内部 stopped 开始 |
| 116.60 s | `goalKick`（away）`placement_started` 事件才发布（**发布滞后约 1.2 s**，与此前各场一致） |
| 116.44–117.73 s | robot2 在球门区角落持续移动：每 0.11 s 步长 0.037–0.057 m（≈**0.40 m/s 平均**），方向沿 `(ball→自身)` 的**反方向**径向向外（即 vacate/crawl 的远离球方向） |
| ~116.9 s | 裁判 grace（1500 ms，自 GC 内部 stopped≈115.4 起算）结束，reference 取此时位置 → 与 evidence reference `(6.888,-4.582)` 精确吻合（帧 116.89 `(6.89,-4.58)`） |
| 117.85 s | robot2 被传送至我方罚下等待区 `(-5.00,5.00)`；从 reference 到传送共 **0.96 s、路径 0.3348 m（≈0.35 m/s）** |

**判读**：这条 0.3348 m **不是 crawl 0.12 造成的**（0.12×0.96=0.115 m），而是「窗口 0.5 s 的 1.0 m/s 快撤」在 grace 尾段仍在执行 + 到达目标前的残余速度；轨迹速度 0.35–0.40 m/s，是 crawl(0.12) 的 3 倍。具体机制：
1. GC 内部 stopped 比我们看到的早约 **1.1–1.2 s**（事件发布 + 话题两重延迟）；
2. 我们检测到 stopped 时 `elapsed = now - (now-0.35) = 0.35 s`，仍 < 0.5 s 窗口 → 触发 `stopped:vacate` 1.0 m/s；
3. 快撤目标 `_away_from_ball_point(ball, pose, 2.0)` 被场边 clamp（球在 `(6.8,-3.8)` 角落，目标只能到 `(6.7,-4.2)`，距 pose 仅 0.54 m）→ 机器人加速到 ~0.4 m/s 后即进入减速/到达；
4. 恰好此时 grace 结束、开始计路径 → 0.96 s 内累计 0.3348 m > 0.3 → 罚单。**真空期只有 0.96 s，而不是 2.37 s**（2372 ms 是事件时间与 GC stopped 起点的差，不是判定窗口长度）。

**建议修法（v2.15 P0）**：
- ① `STOP_STATE_LATENCY_COMP_S 0.35 → 1.15`（对齐实测的 1.1–1.2 s 状态延迟）：检测到 stopped 时 `elapsed≈1.15 > 窗口 0.5`，**直接进入 crawl**，不再有 1.0 m/s 快撤段；
- ② vacate 目标若被 clamp 后离 pose < 0.9 m（本场 0.54 m），**直接 `p.stop()` 不动**（为 0.5 m 的移动吃 0.3 m 罚单不划算；0.96 s 内 0.12 m/s 也只需 0.115 m）；
- ③ `STOP_CRAWL_SPEED 0.12 → 0.10` 可作为**保险**（0.10×2 s=0.20 m），但**单独降 crawl 不够**（本场残差 0.33 m 与 crawl 关系不大；只降速约省 0.02 m）；
- ④ 可选：进入 STOPPED 第一帧先 `p.stop()` 清掉追球动量，下一帧再开始 crawl（启动速度从 0 起）。

**验收（可复跑）**：连续 3 场 manifest `stopped_motion` = 0；回放侧逐帧检查（8.9 Hz）：stopped 段我方非门将**逐帧位移 ≤0.02 m**（=0.18 m/s，crawl 0.12 留 50% 余量）、任意 1 s 窗口路径 ≤0.15 m；R-07/R-06 同时为 0。

**建议（v2.15 P1，很小改动）**：
- `src/player.py attack()`：球在对方门线前 0.8 m 内（`ball.x > half_l - 0.8`）且我方 pose.x > ball.x（机器人已在球的门线侧）时，**先 `release_kick()` + `walk_to((ball.x - 0.45, ball.y), avoid_ball=False)`**，到达后再踢；
- `_behind_ball` 的目标 x 已经在 v2.7 起 clamp 到 ≤ `half_l-0.5`，但**机器人实际位置仍会越线**，建议在 `walk_to` 后加一道 `if pose.x > half_l - 0.35: p.move_to_position((ball.x - 0.6, ball.y))` 的纠偏；
- `_coordinated_kick_plan` 在「空门/无对手 3 m 内」时用 `KICK_POWER_SHOOT_MAX`（7.5）而不是 progress 力度（当前 3.1 m/s 从 7 m 外踢，球滚 6.8 m 就停，差 0.1–0.2 m 到线）。

## 6 v2.15 验收口径补充（回答 T1 ④）

在原有「连续 3 场 R-06/R-07/M-02 = 0、逐帧非门将距球 ≥1.7 m」之上，建议补 4 条（均可从回放/门禁自动核验）：
