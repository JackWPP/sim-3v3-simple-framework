# 参数调优

真实比赛中，往往是细节决定了成败。恰当调整参数，让跑多快、踢多重、站多开表现更好，和复杂策略同样重要。本模块带你认识 `param.py`，把所有可调数值梳理成一张速查表，并交给你一套可复用的调参方法论。调参是最容易上手、也最快见效的提分手段。

🎯 **学习目标**

- 理解 `param.py` 的集中管参思路；
- 掌握控制变量的调参方法论。

---

## 单元1：在 param.py 中管理参数

项目把所有可调数值集中到 `src/param.py`，不用满仓库找硬编码数字。你改 `param.py` 一处，所有引用处自动生效。

```Python
# src/main.py / src/player.py 顶部
from .param import *      # 一次注入，全文件可用 MAX_LINEAR、KICK_POWER_DEFAULT ...
```

这行 `import *` 把 `param.py` 里定义的所有常量名一次性搬进当前模块的命名空间，于是策略代码里可以像用普通变量一样直接写 `MAX_LINEAR`。

策略优化往往伴随着 `main.py` 和 `player.py` 文件反复改写，如果数字散落其中，调参就变成了"全文搜索 + 逐处替换"，极易漏改；集中之后，数值只在 `param.py` 里存在一份，`main.py` 和 `player.py` 都只是引用者，调参简化到在一个地方即可修改所有引用处。

如果你改策略时，涉及到可变更的参数，也要考虑一下这个值应该归 `param` 管吗？

新手优先调这四个对比赛影响较大的参数：

1. `MAX_LINEAR`：机器人跑得够不够快，最直接。但太大易失控/摔倒。
2. `KICK_POWER_DEFAULT`：射门力度。太软够不着门，太猛容易踢飞或自己摔。
3. `SUPPORT_DIST_M`：支援站位松紧，决定阵型攻守平衡。
4. `KICK_ENTER_M` / `KICK_EXIT_M`：追球迟滞，决定进攻稳定性。

## 单元3：调参方法论

很多同学的调参过程是这样的：觉得踢不进 → 把力度从 5 改到 8 → 顺手把速度也从 2 改到 3 → 再把 `SUPPORT_DIST_M` 缩到 2 → 跑一场，赢了。然后就陷入了迷茫，你不知道是哪一个改动起了作用，甚至可能是三个改动互相抵消后靠运气赢的。下次场景一变，全盘失灵。

下面这五步，是一套可以反复执行的调参循环。

**第一步：控制变量，一次只改一个。**

同时改五个参数，等于同时做五个实验却只看一个结果，信息量为零。每轮只动一个参数，其余保持不变；如果两个参数确实存在耦合（比如 `KICK_ENTER_M` 和 `KICK_EXIT_M` 必须保持 `EXIT > ENTER`），就把它们当作一组一起动，但仍然只动这一组。

**第二步：先提假设，再动手。**

不要随便试，而要先把要验证的课题写下来："我认为球总停在门前 1 米处，是因为 `KICK_POWER_DEFAULT` 太小，把它从 5.0 提到 6.5 应该能让球越过门线。" 好假设必须包含现象、归因、预期变化。写下来后，如果结果和预期不符，你可以立刻归因。

**第三步：多尝试，记录数据。**

不要看两眼就下结论。开球、界外球、混战、被压制……不同局面下参数表现可能完全相反（比如大力度在开阔地很好，在门前混战里却容易踢飞）。跑完一场，用文字记下可复述的具体现象："射门 6 次，3 次越过门线，2 次踢偏摔倒"。用数据说话，而不是靠感觉。

**第四步：做对照。**

把改动前的版本（对照组）和改动后的版本（实验组）在同一场景下各跑几次。仿真的好处正是可以重复：同样的开球、同样的对手策略。没有对照组，你分不清是参数变好了，还是这局对手恰好失误。

**第五步：不生效就回滚。**

如果实验组没有明显优于对照组，立刻把参数改回去。参数堆积是调参最大的隐形成本：跑十轮之后 `param.py` 里躺着七个"可能有用"的数字，可能污染任何新实验和Vibe Coding上下文。

<callout emoji="💡">
省时间的调参技巧：先用大步长扫出大致区间，再在最优点附近用小步长测试。
</callout>

> 此步骤可借助AI Assistant完成，参考提示词：请帮我检查当前 param.py 中的参数配置，针对“射门偏软/机器人太慢/支援站位过散”等具体现象，建议一次只调一个参数并给出修改前后的预期影响。

## 🧪 章节练习

思考下面两个场景分别定位要调的参数：

1. **症状：机器人总在己方禁区乱撞门柱。**

> 思考方向：是避障半径太小（`BALL_OBSTACLE_RADIUS` / `SAFETY_MARGIN`）？还是 `SUPPORT_DIST_M` 让它站得太靠近门？或是 `GUARD_FACE_BALL` 站位逻辑问题？

1. **症状：明明到了球边却总踢不进，球软绵绵停在门前。**

> 思考方向：`KICK_POWER_DEFAULT` 太小？`KICK_ENTER_M` 太大导致还没够近就开始踢（踢空）？`CHASE_BEHIND_M` 站位不对导致踢偏？

> 此步骤可借助AI Assistant完成，参考提示词：请根据“机器人总在己方禁区乱撞门柱”和“到了球边却踢不进、球停在门前”两个症状，帮我定位应调整的参数（如 BALL_OBSTACLE_RADIUS、KICK_POWER_DEFAULT、KICK_ENTER_M），并给出修改建议。
