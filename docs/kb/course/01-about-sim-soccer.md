# 01 了解仿真足球赛
> 来源：https://booster.feishu.cn/wiki/KgRKwKDHJi39Bqkre9lc1MoFnIf（原文约 3.3k 字）

## 一、核心要点

- 场地 **长 14 米 × 宽 9 米**，两侧各一个球门；场上无人类运动员，两队各 **3 个机器人**（共 6 台）。
- 规则与人类足球相似：**把球踢进对方球门即得分，得分多者获胜**；有开球、任意球、角球、犯规判罚。
- 机器人**不会自己思考**：只接收指令并行动，不主动判断进攻或防守时机。
- 选手角色是**主教练**，不进入球场，而是开发策略 Agent，告诉三个机器人"往哪跑、要不要拼抢、往哪个方向射门"。
- 比赛节奏极快：**一秒之内可能数次切换攻守态势**，策略需要在 **1/30 秒**内做出反应。
- Agent 的工作循环固定为四步：**看一眼球场 → 想一下策略 → 发一条指令 → 再看下一眼**，周而复始。
- Agent 定义（原文 callout）：**被 Booster Studio 加载、构建、部署到虚拟或真实机器人上的持续决策程序**，比赛中不断"看球场 → 想策略 → 发指令"。
- Agent **不是某个具体机器人**，而是"这支队伍的集体意志"；它每帧只需回答一个问题：**"此刻，我的三个球员该干什么？"**
- 典型场景（原文举例）：对方把球踢出界，裁判判**我方边线球** → Agent 必须立刻识别阶段，**派离球最近的球员去发球、另两人跑位接应**，而不是继续全场追球。"从识别局面到切换打法，就是 Agent 每帧在替你做的事。"
- 开赛三步（原文"3 步开启本地比赛"）：前置条件为已安装 Booster Studio；仿真开始后**三个红色机器人是我方球员**；点击仿真环境顶部 **`Start`** 按钮比赛立刻开始；鼠标可切换比赛视角。
- 上手路径：可在 Booster Studio 中**新建 Agent** 获取策略代码框架，也可直接克隆开源仓库（GitHub：`BoosterRobotics/sim-3V3-simple-framework`；Gitee：`booster_robotics/sim-3v3-simple-framework`）。
- 官方推荐的"Vibe Coding"改法示例：对 Studio 内置 AI 助手说 **"我想让支援球员站得更靠近球一点"**、**"把开球方向改成随机"**，AI 生成/修改代码后重进比赛即可看到行为变化。
- 可扩展的三个层次（原文）：改一个参数 → 加一种角色分工 → 重写整条定位球战术 / 引入机器学习自动决策。
- 背景：**RoboCup 自 1997 年**举办，目标是 **2050 年**一支全自主人形机器人足球队按国际足联规则战胜人类世界冠军队；3V3 仿真赛是**入门门槛低**的组别，不用懂机械、不用调电机，示例策略稍作改动未来可对接真机。

## 三、易错点

- 【原文】**把机器人当自主智能体**。原文明确"它们接收指令并行动，不会主动判断进攻或防守的时机"——所有判断必须写在策略里，没有"机器人自己会补位"这回事。
- 【原文】**以为要"上场操作"**。角色是主教练，不进入球场；操作对象是代码，不是遥控器。
- 【原文】**以为策略只想一次**。策略是"不停运转、周而复始"，每 1/30 秒重算一遍；任何"上一帧的状态"都不能靠局部变量保存（原文在课程 03 才讲 `store`，本篇只强调高频重算）。
- 【原文】**只追球不分阶段**。原文的边线球例子就是反例：不识别 `OUR_SET_PLAY` 而继续全场追球，会白送一次定位球机会。
- 【经验建议】**把 14 × 9 写死进策略**。应统一读 `context.field`（`length` / `width` / `goal_width` / `circle_radius` 等），否则换场地尺寸即失效。
- 【经验建议】**在 `play()` 里做重计算/IO**。1/30 秒预算只有 33 ms，且 `play()` 之后框架还要跑 `debugdraw.flush()`；重计算会直接吃掉反应时间。

## 四、对本项目的具体改进建议

1. **`README.md`**：现在只有 5 行（项目名 + 一句简介）。建议补一节"3 步开赛 + 30 Hz 决策 + 14 m×9 m 场地 + Agent 是球队数字大脑（不是遥控单个机器人）"，与课程 01 对齐；并写明"仿真里三个红色机器人是我方、点 `Start` 开始"，降低新人第一次跑通的门槛。
2. **`src/main.py:_analyze_and_draw`**：按上面的 `context.dt > 0.05` 写法加"帧预算自检"标签（`ns="perf"`）。原文强调"1/30 秒内做出反应"，这是赛场上唯一能直接看到是否超时的低成本手段。
3. **`src/param.py`**：在文件头补一段"标定基准"注释：`FIELD_REF_LENGTH_M = 14.0`、`FIELD_REF_WIDTH_M = 9.0`，并注明 `OPPONENT_RESTART_AVOID_M = 1.65`、`CIRCLE_MARGIN_M = 0.3`、`SUPPORT_DIST_M = 3.0`、`KICKOFF_STAGE_M = 2.0` 都是按 14×9 场地标定的绝对值，场地或机器人尺寸变化时必须重标（**经验建议**）。
4. **`docs/kb/course/`**：新增 `README.md` 作为课程索引（01 概念 → 02 代码分层 → 03 状态机 → 04 Context → 05 Player → 06 store → 07 调参 → 08 FAQ），每条注明对应源码入口函数，避免新人从 `framework/` 开始读（**经验建议**）。
5. **不要动的部分**：原文明确"平台负责把策略 Agent 接入比赛"，即 `src/framework/` 是平台层；课程 01 没有任何要求改它的内容，改它不产生战术收益。

## 五、原文关键摘录

> **3V3 仿真足球赛比的，是会踢球的策略 Agent。你要将对足球的理解，写成策略 Agent。平台负责把策略 Agent 接入比赛，让它在比赛开始后接管决策。你的策略越聪明，球队就踢得越好。**

> 仿真足球赛瞬息万变，一秒之内可能数次切换攻守态势。你的策略需要在 1/30 秒内做出反应，不停运转，周而复始：看一眼球场 → 想一下策略 → 发一条指令 → 再看下一眼。
